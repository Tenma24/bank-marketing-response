## 3. Как заново запустить на Windows

Нужен Python 3.12 — именно на этой версии проверен проект. Откройте PowerShell
в папке, где лежит `README.md`. Команда `Get-Location` покажет текущую папку.

Первый запуск:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe scripts/run_notebook.py
.\.venv\Scripts\python.exe scripts/validate_project.py
.\.venv\Scripts\python.exe scripts/build_reports.py
```

Команды используют интерпретатор из `.venv` напрямую: активировать окружение
и менять PowerShell ExecutionPolicy не требуется. Установка библиотек требует
интернета. CSV уже включён в проект; заново загружать его необязательно.

Успешная проверка выводит `"status": "passed"`. Она проверяет контрольную сумму
данных, разделение, отсутствие пересечения одинаковых наборов признаков,
правильность сохранённых метрик и выполнение notebook без ошибок.

Для работы с ячейками:

```powershell
.\.venv\Scripts\python.exe -m jupyterlab
```

В браузере откройте `notebooks/bank_marketing.ipynb`, затем перезапустите ядро
и выполните все ячейки по порядку. Обучение может занять несколько минут.
Не запускайте последнюю ячейку сразу: она зависит от предыдущих.

Основной поддерживаемый исходник — `src/bank_marketing.py`. Если меняете его,
обновите notebook командой `python scripts/sync_notebook.py`, затем повторите
полное выполнение, проверку и генерацию README/отчётов. В активной `.venv`
используйте её путь к Python, как в командах выше. Не меняйте результаты
вручную: таблицы должны соответствовать реально выполненному коду.

## 4. Как понимать наши результаты

Главная метрика — **F1 положительного класса `yes`**. По validation:

| Модель | Precision | Recall | F1 | ROC-AUC |
|---|---:|---:|---:|---:|
| Decision Tree | 0,353 | 0,622 | 0,450 | 0,784 |
| Linear SVM | 0,348 | 0,630 | 0,448 | 0,791 |
| KNN | 0,585 | 0,274 | 0,373 | 0,770 |
| Baseline «всегда no» | 0 | 0 | 0 | 0,500 |

Decision Tree выбран по заранее определённому F1, но разница с SVM около 0,002:
нельзя утверждать, что дерево уверенно лучше. SVM здесь лучше по ROC-AUC и AP.

Дерево нашло 577 из 928 реальных положительных случаев на validation; пропустило
351. Оно также выдало 1 059 ложных положительных прогнозов. Среди предсказанных
`yes` примерно 35,3% действительно положительные. Это объясняет одновременно
Recall около 62,2% и относительно невысокий Precision.

У baseline Accuracy около 88,7%, выше, чем у дерева. Это не делает baseline
лучшим решением: он вообще не находит оформивших вклад. KNN имеет высокую
обучающую F1 и заметно более слабую validation F1; для KNN обучение оценивается
на точках, содержащих самих себя среди соседей, поэтому этот результат особенно
оптимистичен. Подробности — в разделе error analysis notebook.

У всех моделей результаты относятся к **validation**, а не test и не реальному
будущему периоду. Не называйте 0,450 «45% точности»: это F1, другая метрика.

## 7. Частые вопросы на защите

**Почему классификация?** Ответ имеет два класса: оформил вклад / не оформил.

**Что модель получает на вход?** Атрибуты клиента, история и сведения о
запланированном контакте; `y` — только целевой ответ.

**Почему убрали duration?** До звонка его длительность неизвестна. С ней
качество не соответствовало бы заявленному моменту прогноза.

**Почему не удалили unknown?** Это явно обозначенная неизвестность; массовое
удаление теряло бы наблюдения. One-hot кодирует её как отдельную категорию.

**Что означает pdays=999?** Отсутствие предыдущего контакта. Добавили флаг,
а интервал заполнили на обучающей части внутри Pipeline.

**Зачем масштабирование?** KNN использует расстояния, SVM чувствителен к
масштабу признаков. Дереву стандартизация не нужна.

**Зачем grouping?** После удаления duration встречаются одинаковые входные
наборы. Они остаются вместе, чтобы не пересекать обучение и проверку. Это не
гарантирует разделение по клиентам: ID клиентов отсутствуют.

**Что делает cross-validation?** Модель пять раз проверяется на разных
отложенных частях train. Подготовка заново обучается внутри каждого фолда.

**Почему test не показан?** Это промежуточный этап. Test сохранён для final,
когда решения будут зафиксированы. Сейчас оцениваем CV и validation.

**Можно ли внедрять модель в банк?** Эта работа подтверждает только результат
исторического учебного сравнения. Нужны проверка по времени, уточнение
доступности признаков и проверка бизнес-условий; прибыль здесь не измерялась.
