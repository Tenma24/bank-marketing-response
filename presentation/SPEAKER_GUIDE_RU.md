README, слайды и заметки. Не заменяйте результаты вручную ради лучшего показателя.

## Смысл каждого раздела

1. **Introduction:** прогноз `yes/no` перед запланированным звонком; положительный
   класс означает оформление срочного вклада. Это прогноз, а не доказательство
   того, что звонок вызывает покупку.
2. **Dataset:** 41 188 исторических записей UCI; в train положительных только 11,27%.
   Baseline имеет около 88,73% Accuracy, но никого из положительного класса не находит.
3. **Client characteristics:** распределения возраста пересекаются; различия по
   профессиям — наблюдаемые связи, с разными размерами групп.
4. **Campaign history:** прежний успех связан с большей долей `yes`. Низкая доля
   при многих попытках не доказывает, что дополнительные звонки вредят.
5. **Preparation:** `duration` неизвестна до звонка; `unknown` — отдельная категория;
   `pdays=999` — отсутствие прошлого контакта. Преобразования обучаются внутри фолдов.
6. **Evaluation:** примерно 60/20/20; одинаковые входные профили не пересекают части.
   CV проводится на train, модели сравниваются на validation, test оставлен для final.
7. **Algorithms:** majority baseline, Decision Tree, KNN и Linear SVM; подбор
   гиперпараметров по пяти фолдам и F1 положительного класса.
8. **Results:** Tree F1 = 0,450; SVM = 0,448; KNN = 0,373. Разница Tree/SVM около
   0,002 не позволяет уверенно заявить превосходство дерева. SVM выше по ROC-AUC и AP.
9. **Errors:** дерево нашло 577 положительных, пропустило 351 и дало 1 059 ложных
   срабатываний. Recall = 62,2%, Precision = 35,3%. У KNN большой train/validation gap.
10. **Conclusion:** модели лучше baseline по F1. Для final нужны проверка по времени,
    доступности признаков, порога и один тест после фиксации решений.

Не называйте F1 = 0,450 «45% точности». Не называйте validation результатом на test.
Не обещайте будущую эффективность или прибыль банка: таких измерений нет.

## Как показать работу преподавателю

1. Начните с презентации и пройдите слайды по порядку.
2. Держите рядом выполненный `notebooks/bank_marketing.ipynb` и README с графиками.

4. Оба участника должны понимать всю работу, даже если рассказывают разные слайды.
5. После личной проверки и работы заполните фактический вклад в `docs/TEAM.md`.
